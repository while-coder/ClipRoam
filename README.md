# ClipRoam

ClipRoam用来保存剪贴板历史，并在自己的多台设备之间同步文字、图片、文件和文件夹。

- **Server（服务端）**：部署在一台设备都能访问的电脑或服务器上，负责账号、历史记录和文件同步。
- **App（客户端）**：安装在日常使用的电脑或手机上，用来记录、查找和使用剪贴板内容。

一般只需要部署一个 Server，然后让各台设备上的 App 连接同一个 Server、登录同一个账号。

## Server：部署与管理

### 启动服务

1. 在服务器上安装 Docker。
2. 从 GitHub Container Registry 拉取服务端镜像：

   ```bash
   docker pull ghcr.io/while-coder/cliproam:latest
   ```

3. 启动服务，并填写自己的管理员密码：

   ```bash
   docker run -d --name cliproam-server --restart unless-stopped -p 4810:4810 -e CLIPROAM_ADMIN_PASSWORD="请替换为自己的管理员密码" -v cliproam-data:/root/.cliproam ghcr.io/while-coder/cliproam:latest
   ```

需要固定版本时，将 `latest` 替换为版本号（例如 `0.2.3`）。离线部署可从 [发布页面](https://github.com/while-coder/ClipRoam/releases) 下载 `cliproam-server.tar`，执行 `docker load -i cliproam-server.tar` 后使用相同的镜像名启动。旧版本附件的镜像名可通过 `docker image ls` 查看。

启动后，App 使用的服务器地址为 `http://服务器 IP 或域名:4810`，例如 `http://192.168.1.20:4810`。请确保使用 App 的设备能够访问这个地址；在另一台设备上连接时，不要填写 `127.0.0.1`。

需要使用其他端口时，可将命令中的 `-p 4810:4810` 改成 `-p 8080:4810`，App 中相应填写 `http://服务器地址:8080`。

### 使用管理后台

在浏览器打开 `http://服务器地址:4810`，会自动跳转到管理后台，使用启动时设置的管理员密码登录。管理员密码与 App 的用户账号密码分别使用。

后台可以：

- 查看服务状态和用户数量。
- 管理用户、重置用户密码或删除账号。
- 查看和删除服务器保存的文件。
- 调整历史条数、单次复制文件数和文件大小等限制。

服务端统一提供 HTTP/WS（端口 `4810`），HTTPS 证书和加密连接由反向代理处理。通过公网使用时，在反向代理配置 HTTPS 并启用 WebSocket 转发，代理上游填写 `http://服务端地址:4810`；App 中填写反向代理对外提供的完整 `https://` 地址，管理后台通过代理地址下的 `/admin/` 访问。

使用子路径代理（例如 `/cliproam`）时，需将该前缀下的所有请求去掉前缀后转发，包括 `/cliproam/admin/`、`/cliproam/admin-api/` 和 WebSocket。访问 `/cliproam` 或 `/cliproam/` 会由浏览器跳转至 `/cliproam/admin/`；不带末尾 `/` 的入口也需由代理转发至服务端根路径，或由代理先重定向至带 `/` 的入口。

删除账号会清除该账号的历史；删除服务器文件会影响相关历史内容的再次使用，请在操作前确认。

### 停止、重启与备份

```bash
docker stop cliproam-server
docker start cliproam-server
docker restart cliproam-server
```

账号、历史和文件保存在上面创建的 `cliproam-data` 数据卷中。备份时请先停止服务，再备份整个数据卷；恢复时也需要完整恢复。更新或重新部署时，继续使用这个数据卷即可保留数据。

## App：安装与使用

### 安装和登录

1. 从 [发布页面](https://github.com/while-coder/ClipRoam/releases) 下载适合自己系统的安装包并安装。
2. 打开 App，填写完整的服务器地址，例如 `http://192.168.1.20:4810` 或 `https://clip.example.com`。
3. 使用反向代理子路径时，可填写 `https://example.com/cliproam`；代理需将该前缀下的请求转发至服务端根路径，并支持 WebSocket 转发。
4. 首次使用选择“注册”，创建账号；已有账号则选择“登录”。
5. 在其他设备上填写相同的服务器地址，并登录同一个账号。

不同账号的历史和设备列表互相独立。服务器由别人管理时，向管理员获取完整的服务器地址即可。

地址末尾的 `/` 会自动移除，不影响本地档案。协议或子路径不同的地址使用独立本地档案，子路径区分大小写；更换入口地址后，本地偏好、待上传记录和文件缓存不会自动迁移。若新入口仍指向同一服务端账号，已同步的历史和文件仍可从服务端获取。

### 桌面端：记录和使用剪贴板

保持 App 运行，并在设置中开启“监听剪贴板”。之后像平常一样复制文字、图片、文件或文件夹，内容会自动进入ClipRoam并同步。

- **查找历史**：在主界面的搜索框输入关键词，按 Enter 搜索，也可以按内容类型筛选。
- **复制历史内容**：点击条目，或选中条目后按 Enter，再到目标应用中粘贴。
- **快捷粘贴**：在目标应用中按 `Ctrl + Shift + V`（macOS 为 `Cmd + Shift + V`），选择历史内容即可粘贴。快捷键可以在设置中修改。
- **更多操作**：右键点击条目，可复制、预览图片或文件、另存为或删除。
- **收藏**：收藏时将内容复制到独立的收藏表，同内容重复收藏不会新增副本。删除或自动清理历史不会影响收藏；取消收藏会直接删除收藏副本，不影响历史和便签。

主界面和快捷粘贴共用一个窗口：快捷键切换到无标题栏的快速粘贴模式，两种界面不会同时显示。从托盘选择“显示主界面”可切回完整界面，恢复原来的页面、窗口大小和位置。

macOS 首次使用自动粘贴时，需要在“系统设置 → 隐私与安全性 → 辅助功能”中允许ClipRoam。若无法自动粘贴，可先复制条目，再手动粘贴。

### 桌面便签

在原生桌面 App 的历史记录上右键选择“贴到桌面”，可将已有文字、图片、文件或文件夹显示为独立便签。文字可选择复制，图片自动加载原图（加载失败时保留缩略图），文件夹可展开查看，并可通过“另存为”下载内容。

从桌面侧栏的“便签管理”或移动端底部的“便签”进入管理列表，可搜索、按类型/时间/来源设备筛选、预览、复制、另存为和收藏便签内容，也可单条或批量取消便签。网页和手机端同样可以管理，取消后同步关闭各桌面设备对应的便签窗口；桌面 App 还提供“显示桌面便签”按钮。

- 便签内容独立保存在服务器的便签表中，同账号的其他桌面设备也会显示；登录和重新连接时通过独立接口获取全部便签，不受历史分页、搜索和筛选影响。重装系统后登录即可恢复全部便签。同内容重复贴到桌面不会新增副本。
- 便签按内容自动调整大小，最大 420 × 360 逻辑像素，并受屏幕可用范围限制，不允许手动缩放、最大化或最小化。长文字和文件列表超出范围时滚动显示，大图按比例缩放；图片加载、目录展开和面板切换后自动重新计算大小。
- 窗口位置和置顶状态按本机账号保存；整张便签的不透明度为本机全局设置，所有便签共用，调整任意便签后立即同步到其他便签，切换账号和重启后仍保留。窗口大小每次根据内容重新计算，新设备或本地数据清空后使用默认布局。
- 便签默认保持在普通窗口下方，勾选置顶后固定在最上层；操作便签不获取焦点，不因点击或 Alt 临时操作改变窗口层级。
- 便签默认穿透鼠标，可直接操作下方应用。按住左 Alt（macOS 为 Option）时临时操作便签，松开自动恢复穿透，不需要切换模式。原生层读取按键状态，主窗口隐藏时仍可使用。Linux X11 支持 Alt 临时操作；Wayland 使用托盘备用入口。
- 便签没有右键菜单：平时右键直接穿透；临时操作期间的右键点击会通过系统鼠标事件转发给下方窗口。
- 不透明度按比例影响标题、文字、图片、背景和边框：背景为 0%–100%，文字和图片为 35%–100%，标题及操作栏为 45%–100%，低档仍保留内容可见度。按住 Alt 临时操作或通过托盘进入编辑时会恢复清晰；打开透明度设置后预览所有便签的实际效果，调节面板本身保持可读。面板以浮层显示，不改变便签窗口大小。
- 托盘“编辑便签（解除穿透）”或工作区“显示并编辑便签”作为备用入口，可显示全部并临时保持可操作；点击“完成”，或按住再松开 Alt，即恢复穿透。右上角关闭按钮会直接删除服务器上的便签副本，并同步关闭各设备对应的便签窗口；系统关闭窗口操作执行相同行为。
- 历史、收藏和便签分别保存内容，使用独立 ID。删除或自动清理历史、取消收藏均不影响便签；取消便签也不影响历史和收藏。图片和文件仍共享底层资源，取消收藏或便签不会直接删除共享文件；文件能否再次使用仍取决于本地缓存、服务器存储或在线源设备，创建便签不会自动永久保存文件内容。旧版收藏和便签标记会在服务器首次打开账号数据库时自动迁移为独立副本。
- 每账号默认最多 20 条便签。管理员可在全局或账号传输设置中调整上限（0–100）；设为 0 禁止新增，降低上限不会移除已有便签。

便签接口均需当前账号登录：`GET /entries/sticky` 返回全部便签记录，`PATCH /entries/sticky` 接收 `{ "ids": ["来源记录 ID"], "isSticky": true }` 创建独立副本；取消时传便签自身的 `s-` 前缀 ID 和 `isSticky: false`，直接删除便签。收藏接口 `PATCH /entries/favorite` 同理，取消时传收藏自身的 `f-` 前缀 ID。创建便签超过数量上限返回 409，批量创建整体成功或整体失败。

### 跨设备同步

多台设备连接同一服务器并登录同一账号后，可以查看同一份剪贴板历史。

桌面端开启“自动接收剪贴板”后，其他设备复制的文字、富文本和图片会自动更新本机剪贴板，可直接在当前应用中粘贴。关闭后，仍可从历史中手动选择内容。

文件和文件夹会同步到历史，需要手动选择复制、粘贴或另存为。

### 文件传输

在“设置 → 文件同步”中，可以选择自动上传文件的大小上限，也可以关闭自动上传。

- 已上传到服务器的文件，其他设备使用时无需保持源设备在线。
- 未自动上传的文件，其他设备使用时需要源设备保持在线、App 保持运行，且原文件仍可读取。
- 复制文件后，可在“待上传”中查看处理进度；使用远端文件时，可在“下载”中查看传输进度。
- “下载”记录保存在当前账号的 IndexedDB，各账号独立，重启后仍可查看。每次下载汇总为一条记录，可展开文件详情；保留最近 30 天、最多 500 条已结束记录，也可手动删除或清空。清理记录不会删除已下载的文件。
- 下载过程中遇到网络中断，会在同一次任务内从已写入的位置自动续传，完成后校验文件内容。取消、任务失败或退出 App 后不保留可恢复的续传任务；重启后需要重新下载。
- 不想同步某些文件时，可在“复制过滤”中填写要忽略的名称。
- 预览和复制复用应用下载流程：优先读取本地已有内容，否则完整下载并校验后使用。原生 App 预览、下载均先取得完整本地文件，再读取预览或复制到另存目标位置，本地文件可继续复用；PWA 等 Web 客户端的远程预览、复制使用临时 Blob，不写入 IndexedDB，预览或操作结束且没有其他使用者时释放。上传和待上传内容仍持久化保存。Web 保存单个文件时申请临时 URL，直接交给浏览器下载，不计入应用下载记录；文件夹仍通过目录选择和导出流程保存。大文件预览会占用内存，文本预览完整下载后仅展示前 2 MiB。

### 手机端

手机端可以查看、搜索和删除历史，但不会像桌面端一样持续在后台监听剪贴板。

- 在“剪贴板历史”界面点击“读取当前剪贴板”，导入当前复制的文字。
- 点按历史中的文字，将它复制到系统剪贴板，再到其他应用中粘贴。
- Android 和 iOS 可以通过系统分享菜单，将文字、链接或文件分享给 ClipRoam。截图和照片也按普通文件原样处理。分享入口保存内容后打开主 App，登录和初始化完成后自动导入待上传列表，复用现有上传流程。iOS 未能自动打开时，内容会保留，下次打开 App 后导入。
- Android 点按图片或文件后，选择保存目录即可下载；下载中再次点按同一条目可取消。
- iOS 的图片和文件目前下载到应用缓存，文件导出暂未支持。

### 浏览器端

- **PWA**：Release 发布后自动部署到 [网页版](https://while-coder.github.io/ClipRoam/)。
- **浏览器插件**：从发布页面下载 `ClipRoam_版本号_chrome.zip`，解压后在 Chrome 的 `chrome://extensions` 页面开启开发者模式，选择“加载已解压的扩展程序”，选中包含 `manifest.json` 的目录。
- **Firefox 插件**：下载 `ClipRoam_版本号_firefox.zip` 并解压，在 Firefox 128 或更新版本的 `about:debugging#/runtime/this-firefox` 页面点击“临时载入附加组件”，选择解压目录中的 `manifest.json`。当前产物未签名，临时安装在退出 Firefox 后失效；长期安装需要 Mozilla 签名的 XPI。

### 浏览器端构建与发布

本地运行 `pnpm build:pwa`、`pnpm build:chrome` 或 `pnpm build:firefox`，产物分别位于 `apps/pwa/dist`、`apps/chrome/dist` 和 `apps/firefox/dist`。

推送 `v*` 标签或手动运行 Release 工作流时，会分别构建并上传 Chrome、Firefox 插件 ZIP，同时把 PWA 部署到 `gh-pages` 分支。首次部署后，在仓库 Settings → Pages 中选择 “Deploy from a branch”、`gh-pages` 分支和根目录 `/`；启用后重新运行发布工作流。

PWA 默认使用相对资源路径；部署到子目录时通过 `PWA_BASE` 指定路径，Release 工作流设为 `/ClipRoam/`。

### VS Code 扩展

从发布页面下载 `ClipRoam_版本号_vscode.vsix`，在 VS Code 扩展菜单选择“从 VSIX 安装”。运行命令 `ClipRoam: Open Clipboard History`，连接服务器并登录。

选中编辑器文本后，右键选择 `ClipRoam: Add Selection to History` 可加入同步队列。在ClipRoam历史中复制文本，再回到编辑器粘贴。首版仅支持桌面 VS Code 的文本剪贴板，不持续监听系统复制。

本地运行 `pnpm build:vscode` 构建，`pnpm package:vscode` 生成 `apps/vscode/dist/cliproam.vsix`。Release 工作流同时发布 VSIX；开发和能力说明见 [VS Code 扩展说明](apps/vscode/README.md)。

`pnpm sync:versions` 同步所有客户端包版本、Chrome/Firefox manifest 和 App 的 Rust 版本。`pnpm sync:icons` 从 `apps/icon/icon.png` 生成 App、共享界面、PWA、Chrome、Firefox 和 VS Code 图标；Android、iOS 和 PWA 自适应图标使用全画布的 `apps/icon/icon-fullbleed.png`，由系统裁切；PWA manifest、插件 manifest 和页面 favicon 均引用生成的图标。PWA、Chrome 和 Firefox 的 `public/icons/` 为生成目录，不纳入 Git，开发和构建前会自动生成（仅运行 Web 图标同步）。原生图标按平台输出到 `apps/app/src-tauri/native/{windows,macos,linux,android,ios}/icons/`，不纳入 Git；开发、打包和 Cargo 构建前会自动生成，详见[原生目录说明](apps/app/src-tauri/native/README.md)。

iOS 在 macOS 上使用 `pnpm --filter @cliproam/app ios:init` 初始化，再使用 `ios:dev` / `ios:build`。初始化会重新配置分享扩展、操作扩展、App Group 和图标，CI 使用相同入口。主应用 `com.whilecode.cliproam` 和两个扩展 `.share`、`.action` 的签名配置都需启用 `group.com.whilecode.cliproam` App Group；安装时签名工具必须保留此权限。`prepare.cjs` 为关闭正式签名的设备构建添加 Xcode 临时签名及权限检查阶段，在 Tauri 打包 IPA 前将权限声明写入主程序和两个扩展，再交给 SideStore 或 iLoader 重签名安装。分享入口不保存登录凭据，登录和上传由主应用处理。构建检查不替代设备上的共享容器权限验证。

移动端分享只同步文本和文件。Kotlin 与 Swift 接收并保存分享，随后打开主 App；主界面登录和初始化完成后，将内容导入现有待上传列表。分享入口不执行鉴权或后台上传。目录与构建关系见[移动端分享说明](apps/app/src-tauri/share/README.md)。

### 常见问题

**连接不上服务器**

确认 Server 正在运行，地址和端口填写正确，并且当前设备能访问服务器。直连使用 `http://`，配置 HTTPS 反向代理后使用代理对外提供的 `https://` 地址。必要时请管理员检查代理、网络和端口设置。

**复制的内容没有进入历史**

桌面端确认 App 正在运行且已开启“监听剪贴板”，再检查“待上传”和连接状态。手机端请使用“读取当前剪贴板”，或通过分享菜单导入；打开 ClipRoam 登录后，在“待上传”中查看状态或重试失败项。复制的文件也可能被过滤规则或服务器限制排除。

**历史中的文件无法下载**

若文件没有上传到服务器，请保持源设备在线、App 运行，并确认原文件还在。若服务器上的文件已被删除，需要从源设备重新复制并同步。

# 移动端分享

分享入口只接收和保存内容，随后打开主 App。登录、过滤、哈希、上传限制、同步与重试复用主应用已有的待上传流程。

```text
接收分享 → 保存到本地收件箱 → 打开主 App
         → 登录和初始化完成 → 导入待上传列表 → 现有上传流程

share/
  mod.rs                    # 主应用读取收件箱、复制到账号目录和确认导入
  plugin/
    src/lib.rs              # Tauri 插件：pending / acknowledge
    android/                # ShareReceiverPlugin.kt：接收 Activity、文件访问及共用文件名处理
    ios/
      Sources/SharePlugin.swift  # 共用收件箱、扩展接收和主应用插件
```

## 保存和打开

Android 的 `ShareActivity` 接收 `SEND` / `SEND_MULTIPLE`，将临时 URI 对应的文件复制到应用私有目录 `files/cliproam-shares/<分享ID>/`。文本和附件清单写入临时文件，再原子重命名为 `manifest.json`；提交完成后启动主 `MainActivity`。

iOS 的 Share Extension 将临时附件复制到 App Group 容器的 `ShareInbox/<分享ID>/`，再原子写入 `manifest.json`。扩展沿响应链找到应用 URL 打开器，使用 `cliproam://share` 跳转主 App。主应用在 `native/ios/Info.plist` 注册该 URL Scheme；跳转未成功时，扩展提示内容已保存，用户需重新从分享菜单唤起主 App 后继续导入。该跳转方式需要在目标 iOS 版本上做真机验证。

App Group 默认使用 `group.com.whilecode.cliproam`。SideStore 重签名会追加 Team ID；共用收件箱代码从各自的 `embedded.mobileprovision` 读取带该前缀的实际授权组名。主应用与分享扩展必须获得同一组的授权，安装时须保留分享扩展。此适配需要重新构建 IPA，仅刷新旧包的签名不会更新代码。

iOS 同时提供上方 App 区域的分享入口 `ClipRoamShare`（`com.apple.share-services`）和下方操作列表的「保存到 ClipRoam」`ClipRoamAction`（`com.apple.ui-services`）。两个扩展复用同一份 Swift 源码、内容类型规则及 App Group 收件箱；后续导入流程相同。安装新 IPA 时需保留两个扩展，可在系统分享面板的「编辑操作」中启用操作入口。

图片与其他文件都按原文件保存，不在分享入口转换、哈希或上传。没有提交清单的目录不会被导入。

## 主应用导入

`packages/ui/src/features/shares/useShareReceiver.ts` 等待主界面登录条件满足，`importPendingShares.ts` 等待账号初始化后调用现有 `CaptureService` 导入待上传列表。iOS 仅在收到 `cliproam://share` 唤起后读取 App Group 收件箱；普通启动、回到前台或切换账号不读取收件箱。冷启动时暂存唤起请求，直到登录和初始化完成后处理；请求读取失败后不会随前台切换反复重试，需要再次从分享入口唤起。其他平台继续在挂载监听、回到前台或账号就绪时检查收件箱。

分享使用稳定的 capture ID，部分成功后重试不会重复入队。只有整个分享成功导入后，才调用 `acknowledge` 删除原生收件箱内容；失败时保留，供下次导入。原生附件先复制到账号目录，清理收件箱不影响待上传文件。

新分享由导入时登录的账号接收。旧上传器遗留的清单仍可读取；带 `ownerScope` 的分享只允许对应账号导入。主应用同时兼容旧 iOS 的 `share.json` 清单。

分享入口不保存服务器地址或登录凭据，不执行鉴权，也不创建独立后台上传任务。

## 构建

Android 插件作为 Gradle library 编译，接收 Activity、主应用插件和文件名处理合并在 `ShareReceiverPlugin.kt`。iOS 共用收件箱、扩展接收和主应用插件合并在 `Sources/SharePlugin.swift`；准备脚本 `../native/ios/prepare.cjs` 将此文件分别复制到生成的分享扩展和操作扩展，并启用 `CLIPROAM_SHARE_EXTENSION` 编译条件，只编译扩展入口与共用收件箱。主应用通过 Swift Package 编译同一文件中的插件入口与共用收件箱。扩展不链接 Tauri 或独立 Rust 静态库。

生成工程位于 `../gen/`，不直接维护。构建入口仍为 `pnpm --filter @cliproam/app android:init` / `ios:init` 及对应的 `dev` / `build` 命令。

插件的前端权限只保留事件监听注册和注销；收件箱读取与确认通过主应用 Rust 命令调用。权限文档 `permissions/autogenerated/reference.md` 和 schema `permissions/schemas/schema.json` 由 Tauri 构建生成，不纳入版本管理。Android 插件作为主工程的子项目接入，不维护独立 `settings.gradle`。
